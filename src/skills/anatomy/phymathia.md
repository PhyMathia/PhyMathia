# 精工等距图（本节点唯一的画法契约）

本节点只按这一套画，不要再叠加别的画法条款。

- **适用**：用户要看清一个真实装置长什么样、零件怎么咬合、动作怎么传——发动机、泵、阀门、齿轮箱、机芯、仪器、工装夹具、实验台。也适用于「这条系统怎么工作」需要用一个具体物件来承载的场合。
- **不适用**：函数图像、概率分布、矢量场、纯流程、纯推导、只求一个结论。这些走普通图表，不要把曲线硬塞进机器里。
- **与「等距剖视画法」的关系**：那是简版（12–24 个零件、440×400），本契约是精工版。同一次生成只可能拿到其中一条，按拿到的这条执行，不要混用两套尺寸与零件数。

## 一、一条铁律：物体本身就是解释

不要画方框、箭头、标签。**要发明一个真实的、做得像样的物件，它的运转本身就是那个概念。**

先写清两件事再动几何：这个东西替人干什么活；谁把运动或信号传给谁。写不出这两句，说明物件选错了。

两个常见死法：
- **太抽象**——层叠的板、悬浮的块、贴了字的盒子。读者认不出是什么，解释就落空。
- **太空太平**——一整块大板画几根线。没有体积、没有零件、没有可发现的东西。

解法只有一个：一个一眼认得出的机器，由许多小而精确、各有用途的零件组成。要表达「分层」，就做成抽屉、机架上的托盘、导柱上的板、卡片匣——而不是一堆浮着的薄片。

## 二、画布与外部契约（宿主硬要求，先满足再谈好看）

1. 根元素写 `lang="zh-CN" data-theme="light"`；`:root` 与 `html[data-theme="dark"]` 各定义一套 CSS 变量，**颜色一律取变量，不写死色值**。
2. 字体只用系统栈；**不引任何外部字体、图标库、图表库、图片、`<script src>`、`<link href>`**。本页必须能离线打开。
3. 主图用 SVG：`viewBox="0 0 600 360"`，`preserveAspectRatio="xMidYMid meet"`，宽高 100%。版式＝左侧主图占满剩余宽度 + 右侧读数面板固定 170–180px；容器窄于 560px 时读数移到下方。
4. **不用 WebGL、不用 canvas**。全部几何在 SVG 里画完（本页不引任何库，着色器没有落地条件）。
5. 线宽 0.6–1px，细而稳。一屏里的视觉层级不超过三层：底、结构、主体。

## 三、部件词典（照着搭，不要自创形状）

物件由「底座 → 结构 → 机构 → 控件 → 主体」五段搭出来。每段挑 3–8 个零件，总数落在 **24–60 个实体**（这里的实体指有体积的块、柱、盘、管，不含刻度和螺钉点）。

| 段 | 零件与做法 |
|---|---|
| 底座 | 带脚的地板/底板：板厚 10–14，四角或六处圆脚（法兰 + 脚两段圆柱，脚比法兰小一号）；板下加一层模糊halo，让它落在光里 |
| 刻度 | 贴边的尺条：主刻度高、次刻度矮、零位加粗；刻度**必须挂在尺条边缘**，不许悬空浮在板上 |
| 结构 | 立柱、导轨、横梁、端挡；立柱穿卡箍时**上下分两段画**，中间那段夹住 |
| 机构 | 滑块（导轨上的套筒 + 压板）、绕杆弹簧、连杆、活塞、偏心轮、齿条、皮带 |
| 控件 | 滚花旋钮（两三个同心圆柱 + 一圈短径向纹 + 一个指针缺口）、手拧螺丝、拨杆、提手 |
| 主体 | 被解释的那个东西本身，用最亮的一档；只有一个 |
| 连接 | 螺钉/铆钉画成小圆点，直径 0.8–1.2；管路两端必须有法兰或接头，落在真实接口上 |

几条硬细节：
- **每个零件都坐在另一个零件上**。板在脚上，脚在地板上，导轨在板上，滑块在导轨上，表在卡箍上。悬空即为错。
- **弹簧绕杆时必须切成两半**：后半圈 → 杆 → 前半圈，否则画家顺序没有解。
- **管子不许穿管子、不许穿零件**。走线先定两端真接口，再沿结构走，交叉只发生在直段上。
- **表面纹理要收在真边缘上**：散热孔阵列要么排到边、要么逐渐变淡消失，不许在半路突然断掉。

## 四、五档明暗（只用这五档）

| 用途 | 档位 |
|---|---|
| 底座、脚、地板 | 暗（lo） |
| 结构：立柱、导轨、横梁、滑块、外壳 | 中（mid） |
| 主体（被解释的那个东西） | 亮（hi） |
| 此刻该看的那个零件 | 高光（lit，**全图只许一个**） |
| 凹槽、内缩线、地面网格 | 极淡（faint） |

- 每个零件有厚度就要有侧面：顶面最亮、两个侧面各一档，四档之间**亮度差控制在 3% 左右**，靠色差读体积，不靠黑白对比。
- `lit` 那一个加白边 + 更亮的顶面，它必须是会动的那个（活塞、指针、滑块、抽屉）。
- 整体保持单色系；只有「颜色本身是主题」时才用真实彩色，且只用一个点缀色。油、水、冷却液默认是本图的墨色深浅，不是橙的蓝的。
- 零件之间的折线（顶面与侧面交界）用极淡色描一道，比加阴影更省。

## 五、画家顺序（决定「像不像实物」的一半）

1. **先画底，再画坐在它上面的**；同一层内按深度从小到大（远先近后）。
2. **会包住别人的零件必须切开画**：弹簧绕杆、框架围滑块、壳体包内腔——后半 → 里面的零件 → 前半。
3. **运动件画在它物理位置对应的那一格**，外层套一个 `<g transform>` 移动它；如果它既要跑到某个邻居前面又要跑到后面，就切开那个邻居，或限制行程让顺序不变。
4. **穿过别人身体的竖直件分段画**（立柱穿过夹板：夹板下、夹板上两段）。
5. **一截管子/线缆按「段」排深度**：一根线可以在这段跑到零件前面、下段跑到后面；两线交叉时以离观者近的那段后画。
6. 手调顺序超过二三十个零件后会互相打架。规则上只认一条：**按真实几何深度排，不按看起来顺眼排**。真排不出来，说明有零件该切开。

## 六、相机与构图

- 默认方位角 45°、仰角 30°。把**带机构的那一面**转向观者：需要看长边就用 35–60°，需要看进敞口（水槽、料斗、敞开的机箱）就抬到 40–44°。
- 物件占画面的 55%–65%，四周留白，不压到四角注记。同一组图之间尺寸感要一致。
- 卡片四角：左上 `图 n`，右上短标题（不超过 8 字），左下交互提示（「拖动旋钮」），右下实时读数。图例与一句真实说明放在卡片下方。**图内最多一个极小的蚀刻字**，其余文字一律出图。
- 等距投影的自检：三个轴上的等长线段在屏幕上应等长；圆在顶面应是椭圆（长短轴比约 1.73:1），不许画成正圆。

## 七、运动：慢、缓、有物理

- **时间驱动**：从 `requestAnimationFrame` 的时间戳取 `dt`，并夹到 1/30 秒，防止后台标签页回来一跳。
- **缓动而非跟手**：指针只设「目标值」，零件用指数缓动追过去 `x += (target − x)·(1 − e^(−dt/τ))`，τ 取 0.1–0.3 秒。**绝不允许零件瞬移到光标**。
- **该弹的用真弹簧**：给刚度和阻尼，约每秒 240 次子步保证稳定；误差和速度都小于 5e-4 时吸附到目标。
- **一个循环**：一个 `tick(dt)` 先算模型，再改 DOM（`setAttribute('transform'|'d')`、`textContent`），不要每帧重建节点。
- **无人操作时放一段约 8 秒的巡演**，把这张图要说明的那件事演一遍；悬停/按下即暂停，最后一次交互后 3.6 秒恢复。
- **尊重减弱动效**：`prefers-reduced-motion: reduce` 时直接跳目标，不巡演，但仍要响应输入。
- 已停稳或不可见就停掉循环（`IntersectionObserver`，`rootMargin: "120px 0px"`，取 `entries[entries.length - 1]`——取第一条会让图冻在屏上）。

## 八、读数必须实算，且同刻同源

- 读数来自驱动零件的**同一个模型**，单位真实、措辞短：`行程 42.0 mm · 泄漏 0.3 mL`、`曲轴 120° · 压力 1.8 MPa`。
- 从零件的**实际位置**读，不从目标值读：正在动就说「正在装配」，停稳了才说「已拆开 · 11 组」。
- 一句话里的状态词和数字必须取自同一时刻的同一来源（状态词来自模型、数字来自一个慢 0.25 秒的表针，就会出现「阀刚开、读数还是老值」）。
- 算不出来的量（温度、压力、效率）只做色块示意，并在卡片下方注明「示意，非计算值」。**不许把示意值写成计算值。**

## 九、反模式（每一条都是被判过不合格的）

- 悬浮的板、抽象的层、贴字的盒子。
- 一整块大平面加几根线。
- 蓝图式标注：引出线、编号气泡、尺寸箭头、剖面线、虚线隐藏边、漂浮标签。
- 线在半空停住；连接线差一截没接上零件；折线没走到轮廓角。
- 线框透视（能看见背面的边）。
- 满图彩色；除非颜色是主题。
- 图里写字（最多一个蚀刻标签）。
- 纹理半路骤停；曲面用阶梯色块冒充明暗。
- 零件瞬移到鼠标。
- 管子穿管子、管子穿零件。
- 同一处被否两三次还在调参数——先问「这个零件该不该存在」。

## 十、交付前自检（不用跑脚本，逐条肉眼过）

1. 盖住标题，还能一眼说出这是什么物件吗？
2. 有没有哪个零件是悬空的、或者压在空气上？
3. 有没有两条线交叉却没分前后？有没有管子穿进零件？
4. 高光零件是不是只有一个？它在动吗？
5. 三个轴的等长线段在屏幕上等长吗？顶面的圆是不是椭圆？
6. 读数里的每个数字都能从模型推出来吗？有没有把示意写成计算值？
7. 缩到 390px 宽还看得懂吗？读数是否已落到下方？
8. 深色主题下还有对比度吗（所有颜色都取变量的话，应该自动成立）？

四条都过不去的图，不如退回到零件少一半的版本——**清楚胜过密**。
